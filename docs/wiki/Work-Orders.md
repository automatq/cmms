# Work Orders

Work orders are the unit of work in MainTek. Each one has a type, a priority, a status, an
optional asset and location, an assignee, a checklist, labor and parts logs, attachments,
comments and a time log of technician sessions.

## Types and priorities

| Type | Priority |
|---|---|
| `corrective`, `preventive`, `inspection`, `emergency` | `critical`, `high`, `medium`, `low` |

Preventive work orders are usually created by the PM scheduler; the others are created by
people, from the public request portal, or from a QR scan.

## Lifecycle

```
requested ──> pending_approval ──> open ──> in_progress ──> completed
     │               │              │  ▲         │
     │               │              │  └─────────┤ on_hold (awaiting_parts | awaiting_approval |
     │               │              │            │          safety_lockout | scheduling | other)
     └───────────────┴──────────────┴────────────┴──> cancelled
```

Allowed transitions are enforced by a state machine in the API (`work-orders` module,
covered by unit tests). Completing from `requested` or `pending_approval` is allowed so a
quick fix does not need to walk every step. Completion records who finished it and when,
closes any open technician sessions, and fires `wo.completed` to webhooks.

## Working with them

- **Views.** `/dashboard/work-orders` offers a list, a dense table, and a kanban board
  with drag-and-drop between status columns. Filters are multi-select (status, priority,
  type, assignee, asset, location, date range) and bulk actions apply to the selection.
- **Create.** A drawer form with inline validation; required fields are title, type and
  priority. Pick an asset to inherit its location.
- **Detail page.** One status control shows the valid next states. Tabs for checklist,
  labor, parts, attachments, comments and time log. An AI panel offers a summary,
  troubleshooting steps and recommendations for the asset.
- **Assignment.** Assign a technician; they receive an in-app notification, an email, and
  a push notification on mobile.
- **Comments.** Markdown-lite comments with `@mentions`. Mentioned users get a clickable
  notification that deep-links to the thread.
- **Time log.** Technicians start a session by scanning the asset QR code (web `/scan` page
  or the mobile scanner) or from the work order. Sessions record who worked and for how
  long; abandoning a session is possible and tracked.
- **Checklists.** Attach a checklist template (from PM templates or ad hoc). Each item can
  be ticked, annotated and photographed.
- **Labor and parts.** Log hours per user with a rate; consume parts from a storeroom,
  which creates an inventory transaction and feeds cost reports.

## Numbering

`WO-<year>-<sequence>` per organization, generated by the API.
